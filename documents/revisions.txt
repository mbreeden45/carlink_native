[62] :: Reliability + mic overhaul (untested on vehicle; unit-tested + builds).
        * Connection: new ConnectionSupervisor owns connect/retry in its own scope (was a UI-scoped suspend fun; a recomposition cancelled it mid-connect and left the UI on 'Connecting...' forever). Single-flight, runs on IO (init sequence used to Thread.sleep on the main thread), retries forever with capped backoff, watchdog restarts a silent/stalled adapter.
        * USB: ACTION_USB_DEVICE_ATTACHED is delivered to the Activity, never to dynamic receivers -> removed dead receiver, handle it in onCreate/onNewIntent, launchMode singleTask. USB permission wait raised 30s->5min (a late 'Allow' used to be discarded then re-prompted); refusal backs off 60s. Removed dead UsbDeviceManager/BulkTransferManager (had a second, conflicting VID/PID table).
        * Mic: adapter commands START_RECORD_AUDIO/STOP_RECORD_AUDIO were ignored (only Siri/phone-call commands started the mic) -> voice messages/Snapchat got silence. Now handled. Capture thread sends directly (Timer + ring buffer removed). AudioSource fallback chain with silence probe + silenced-client diagnostics. Foreground service now declares/uses the microphone type (Android silences AudioRecord for non-visible apps otherwise).
        * Audio: AudioFocusController (per-stream focus matching AAOS CarAudioContexts; cooldown after permanent loss; Settings toggle; off in Bluetooth audio mode). Mic source + audio-transfer mode are re-asserted to the adapter every session.
        * Build: own applicationId (com.mbreeden.carlink, override with -Pcarlink.applicationId), optional release signing via signing.properties/env, unit tests (43), GitHub Actions CI + tagged release AAB.
